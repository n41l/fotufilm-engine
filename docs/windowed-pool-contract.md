# Stage19: original windowed buffer-pool forensics and bounded best-fit

This is an isolated macOS host-allocation experiment on frozen R96623ba0831a52dbddcda35727a206d4123a8b5f and its complete original63-archive AOT set. Candidate production sources, defaults, graph math, shaders, ABI, windows and public controls stay unchanged. Research code lives in tools and is appended only to generated diagnostic copies of the R shim. No MTF/Coupler fusion is enabled.

Original allocation forensics uses six count-based consecutive frames per HD/UHD case, both a light worker and an observed worker. The observer renames original allocation/reference/commit functions only in shim.o, delegates to them unchanged, and takes read-only snapshots before/after allocation. It records physical identity, requested/rounded/actual length, pool state, fence status, physical deallocation and lease roles. GPU status may progress between observations. Detailed workers perturb scheduling; their latency/process footprint is not a performance result. Light counts provide an independent check. Field names and allocation-time costs are not inferred from sizes alone.

Original UHD reproduces four fresh48MiB intermediate buffers per warm frame. At the next frame's first24KiB request, reclaiming returned buffers removes four completed48MiB buffers; idle481.19MiB plus returned700.06MiB exceed the1GiB idle cap. Larger56/72MiB buffers remain idle when new48MiB requests arrive. Both the capacity rule and exact-bin matching matter. This is not evidence that pool fences may be ignored.

The proposed suffix changes only selection: exact match first; when missing and rounded request is at least64KiB, take the smallest idle buffer between rounded size and1.5×rounded. Tiny buffers stay exact. Subtract the actual buffer size from idle accounting and preserve its original physical length in ownership metadata. Reclamation, fence/reference handling, allocation rounding and1GiB cap remain unchanged. The suffix has no production/default activation. Larger allocation bounds must satisfy every logical request, and the existing resource observer must prove GPU-safe reuse.

Before timing, six primary/odd/nonlinear frozen cases use the normal benchmark worker and must match independent R output SHA, actual variant, single AOT and dispatch count. Count-based light/detail runs use six consecutive frames per HD/UHD; a twelve-frame mixed history visits all six cases forward and backward in one process. Detailed allocation traces must have no ledger errors, completed GPU fences and physical length>=requested for every lease. Original and candidate keep the original1e-5/encoded<1/255 correctness contract; all current cases pass the stronger exact-SHA criterion. Resource analysis regression tests run before timing. There is no film/AOT source change requiring a new shader release/parity build; broader all-stock/holdout and promotion remain separate pending work.

Timing is predeclared at twelve rounds: original R vs BestFit, three repeats per arm/case on Portra Coffee1920x1080 and3840x2160. HD orders R/BestFit, BestFit/R, R/BestFit; UHD reverses these, balancing first position across the campaign. Both use the unchanged common benchmark, fresh processes,5s warm/30s measure/2s tail/5s idle, one in-flight frame,1GiB pool,1GiB free-disk reserve and256MiB evidence budget. No detailed observer, builds, GPU verification, plots or cleanup during timing. All own-arm hashes/actual/one-AOT/dispatch checks remain required. Docker and user services stay running. Preserve every round and failure; do not interpret protocol validity as a stable B_ref.

Report all round medians, worst p95, repeated device peaks and per-frame new-buffer histograms. Fixed six-frame resource results are preliminary, not warm timing results. A memory or allocation win does not imply a speedup. Variable-size history results remain distinct from repeated same-case results. No default activation, Taggii integration, push or upstream PR is authorized by this diagnostic's outcome.
