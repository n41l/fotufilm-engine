# Stage21: per-Metal-method timing and command-queue backpressure

Extend the unchanged stage20 base observer in a separate diagnostic adapter. Production/default sources, shaders, film mathematics, ABI, window size and allocation policy remain unchanged. Use frozen R96623ba and the original63 AOT archives; BestFit still uses only the isolated bounded allocation suffix. Queue capacity stays at the original4 non-completed command buffers. Source and observed queue-construction arguments both confirm this value; it is unrelated to the number of image-processing stages.

Three fresh-process modes per policy: off (base probes disabled), basic (unchanged base lifecycle probes) and detail (base plus process-local method observers). All three perform the same tiny dummy-library/class setup before timing, avoiding an initialization difference unique to detail mode. The detailed adapter observes commandBuffer creation, compute encoder creation, newFunctionWithName, newComputePipelineStateWithFunction:error, pipeline binding, setBuffer, setBytes, threadgroup memory, dispatch, endEncoding and commit. Argument buffer lengths are read outside the timed binding method. Detailed method time is CPU-side elapsed wall time and includes descheduling; it is not active CPU time.

Separate the outer commandBuffer observer from the original native IMP called by the base probe. The outer interval includes base bookkeeping, detail metadata and possible descheduling. The native interval excludes that wrapper bookkeeping, while other installed process-local observers may still run inside native Metal internals. Do not sum the nested outer/native intervals or subtract a constant correction. Record actual queue limit and callback-pending count before each native acquisition. Callback-pending includes completion-delivery lag and is not exact GPU queue occupancy.

Assign a new generation token on every native commandBuffer acquisition, since Metal reuses object addresses even within a frame. Link every Halide command once to its existing base GPU record and kernel label. Require native/outer acquisition and commit for every command, and encoder/function/pipeline/bind/threadgroup/dispatch/end coverage for each compute command. Keep buffer binding lengths/indices. The first detailed pilot was exploratory; the next cold preflight stopped on duplicate tokens caused by address reuse. Its images matched but its associations were invalid. Preserve it and rerun all preflight checks after fixing generation identity; do not relax coverage.

For each encoding envelope, clip the timed native method intervals and compute their union and residual. Exclude the outer factory wrapper and commit from that native encoding coverage. Nested method durations and the residual are not independently additive to CPU/GPU times. Compute native-factory overlap with previously submitted GPU intervals as an observation of backpressure, not proof of exact driver internals. Retain unlinked native events separately; require complete Halide command links and observed capacity4. No added API-internal waits, counter sampling or per-kernel serialization.

Final preflight: six frozen fixtures × two policies × off/basic/detail=36 fresh processes. Full original output SHA, finite/alpha, actual symbol, one AOT, dispatch, base timestamp/CPU allocation coverage and detailed command/method coverage must pass. Eight new interval/link/queue tests plus nine base-probe and thirteen existing resource tests pass before sampling. The final adapter and all builder sources are fingerprinted and snapshotted.

Predeclared diagnostic cohort: Portra Coffee1920x1080 and3840x2160, six cyclic Latin-square repeats of the six cells, UHD using each reversed order. Total72 fresh processes,10 warm+12 measured frames per process,864 measured frames. One in-flight frame, original1GiB pool, unchanged queue depth4,1GiB free-disk reserve and256MiB cohort evidence budget. Use caffeinate; no native builds, GPU verification, plots or cleanup while this cohort runs. Docker and user services remain running. This short count-based attribution is independent of stage19/20 datasets and does not freeze a B_ref or pass release performance gates.

Report all process medians and per-call/per-command distributions, native versus outer factory durations, method coverage/residual, factory/previous-GPU overlap, actual capacity and pending histograms, plus off/basic/detail API and CPU calibration. Observers and trace I/O may change scheduling and comparison direction; do not claim a causal BestFit slowdown unless the controls support it. The original source explicitly describes depth4 as host throttling to let GPU frees arrive and limit intermediate memory. Do not increase queue depth or remove fences in this experiment. No Taggii integration, default activation, push or PR.
