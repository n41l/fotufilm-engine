# Stage20: CPU allocation, encoding, GPU command and synchronization probes

Use frozen R96623ba and its full original63 AOT archives, with the stage19 bounded-best-fit suffix as the only policy difference. Production sources/defaults, shaders, image formulas and ABI stay unchanged. Each policy has one worker with probes enabled/disabled at launch. No MTF/Coupler fusion or new wavefront stage is involved.

Instrumentation is confined to generated shim copies, the external driver and a process-local adapter. Exact-count text replacements insert RAII scopes at original pool reclamation and physical eviction-release sites; the original source file is never edited. Metadata saves original/transformed/prefix/suffix SHA and replacements. Original helpers are renamed only in shim.o so external wrappers can measure inclusive allocation and runtime release. Process-local Metal method observers measure the actual newBufferWithLength call and waitUntilCompleted. Command creation→commit entry is an encoding envelope, not pure active CPU time. CPU scope elapsed times include descheduling and nested probe overhead. The frame's main-thread user+system CPU time is sampled around the API with Mach thread_info and includes sampling margin.

For every Halide command commit, record its existing label and GPUStartTime/GPUEndTime in a completion callback. The observed runtime submits one compute command buffer per kernel and labels it with the entry name; enforce kernel interval count==actual dispatch count. Also retain sync/blit commands. Validate positive kernel timestamps, successful completion and Metal/host clock alignment within the API. Completion callbacks are drained after the API returns; this diagnostic drain and trace serialization are excluded from API elapsed time and reported separately. No extra wait is inserted inside the API, and no Metal counter sampling or per-kernel serialization is enabled.

Metal command intervals overlap in the pilot. Therefore retain individual intervals and report their union, span and sum separately. The union is GPU-reported execution coverage, not hardware utilization or active cycles. Per-kernel durations are execution envelopes, not additive stage costs. CPU wait overlaps GPU execution; allocator includes reclamation and physical release, so these categories must not be stacked or subtracted as independent totals. Driver new-buffer CPU duration does not cover memory initialization/mapping work deferred elsewhere. Kernel internals, cache/DRAM/spill and every possible synchronization mechanism are outside this probe's scope.

Preflight: six frozen primary/odd/nonlinear fixtures × two policies × probes on/off=24 fresh processes, one fully verified image each. Full output SHA must match independent original proof; finite/alpha, symbol, one AOT and dispatch remain checked. On-mode coverage must include all successful Metal allocations, all kernel command timestamps and every observed command's encoding envelope; waits must be observed. Off-mode CPU/GPU probe arrays must be empty, never reported as zero GPU time. Regression tests cover interval union/overlap, missing/failed timestamps, clock/dispatch/allocation coverage and frozen-source transform boundaries. Preserve the initial compile failure (missing clock declaration, fixed before GPU execution) and earlier pilot evidence separately.

Count-based diagnostic cohort: Portra Coffee1920x1080 and3840x2160; four Latin-square repeats of R-off/R-on/BestFit-off/BestFit-on,32 fresh processes total. UHD reverses each HD order. Each process uses10 warm frames and40 measured frames, one in-flight frame, original1GiB pool; full hashes at warm/measurement boundaries, actual symbol/AOT/dispatch on every call. Maintain1GiB free disk and256MiB evidence budget. Use a caffeinate wrapper to prevent idle sleep. No native builds, GPU verification, plots or cleanup during this sampling cohort; Docker and user services remain running. This is separate from stage19's time-window benchmark; do not splice the datasets or call the count-based result a release acceptance. Probe/off comparisons describe observed instrumentation effects, including trace I/O between calls; do not subtract them as an exact correction.

Report CPU allocator/new-buffer/reclaim/eviction/runtime-release/commit/encoding elapsed times, main-thread CPU, wait wall time and overlap, per-kernel GPU intervals/union/span, submit-entry→GPU-start delay (not pure queue/fence wait), flush cost, allocation counts and memory. All per-frame/per-command raw data and unsuccessful paths remain retained. Formal all-stock/holdout, concurrent workloads, stable baseline and default promotion remain pending. No Taggii change, push or upstream PR.
